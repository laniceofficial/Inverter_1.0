### CAN的修改
**核心修改：分发器机制**
- 主要提要：反正用法没差
- 主要修改文件：can/fdcan
- 主要思路：优化回调函数机制，使用统一分发器，避免使用链表轮询
- 主要方法：`查表，全局分发器（静态实现）static std::map<CANKey, CAN_Rx_Callback_t> can_callbacks_map;`
 (补充：std::map是C++标准库中的关联容器，用于存储键值对，允许通过键快速查找对应的值，
键：CANKey是自定义类型，用来标识一条 CAN 报文的“身份”，
值：CAN_Rx_Callback_t这是回调函数类型，即收到指定 CAN 报文时要调用的函数，)
  ```cpp
  // std::map使用举例
  #include <map>
  #include <string>
  #include <iostream>
    
  int main() {
  std::map<std::string, int> score;  // 键是string，值是int
    
      score["Alice"] = 95;
      score["Bob"] = 87;
      score["Carol"] = 100;
    
      std::cout << score["Alice"] << std::endl; // 输出 95
  }
   
  // 修改后的CAN里面全局分发器（静态实现）
  struct CANKey {
  CAN_HandleTypeDef* can_handle;
  uint32_t rx_id;
    
      bool operator<(const CANKey& other) const {
          if (can_handle != other.can_handle) {
              return can_handle < other.can_handle;
          }
          return rx_id < other.rx_id;
      }
  };
  static std::map<CANKey, CAN_Rx_Callback_t> can_callbacks_map;   

  // 在构造函数里把回调注册到分发器
  if (can_module_callback_)
  {
  CANKey key{can_handle_, rx_id_};
  can_callbacks_map[key] = can_module_callback_;
  }
  ```
