因为本地flash就一个所以搞单例

本地flash-log遵循以下协议

*  一个Flash扇区(128K)被分为9个区域(config->Notice->Warning->Error->Fatal->UserDef1~4), 各区域flash空间按顺序相互连接
*  起始 9 字用来储存log配置(8组区域对应起始地址与最终结束地址), 存储在config区
*  区域内以"信息(message)"为单位储存数据, 每条信息第一个uint32_t记录下一条信息首地址, 信息的最后一个uint32_t记录此信息的首地址


## 1. 初始化

```c++
// 初始化传参结构体
Log_n::Base_Config_t config = {
            .is_reset = true, // 是否重烧flash配置
            .zone_size = {	  // 配置各区域大小(单位 字)，默认为0
                // 特别注意！H7配置区域大小时会将区域首地址32字节向上对齐，实际区域大小可能会大于你设定的大小
                // 总上限32758字(130744字节), 保险起见, H7定义32686字(130744字节)绝对不会超出上限
                    .notice_size = 1024,
                    .warning_size = 1024,
                    .error_size = 1024,
                    .fatal_size = 256,
                    .def1_size = 29358,
                    .def2_size = 0,
                    .def3_size = 0,
                    .def4_size = 0,
                // 超出上限会自动缩小空间
            }
    };

// 初始化--两者都可以
Log_n::LocalFlash_c::Init(config);
Log_n::LocalFlash_c* ptr = Log_n::LocalFlash_c::Get_InstancePtr(config);

// 获取单例--两者都可以
Log_n::LocalFlash_c* ptr = Log_n::LocalFlash_c::Get_InstancePtr();
Log_n::LocalFlash_c* ptr = Log_n::LocalFlash_c::Get_InstancePtr(config);

// 可以在初始化后通过working_statue()方法获取成员变量判断初始化是否成功
WorkingStatus_e statue;
statue = ptr->working_statue();
if(statue != WorkingStatus_e::Normal)
{
    // 初始化没成功
}

// 可以通过这种方法查看实际分配区域大小
Log_n::LocalFlash_c::ZoneAddr_t zone_space = (++ptr->zone_start_addr()) - ptr->zone_start_addr();
```



## 2. 基类 继承/重写 功能

```c++
Log_n::LocalFlash_c* ptr = Log_n::LocalFlash_c::Get_InstancePtr();

/**
 * @brief 获取指定区域内信息数(成员变量message_num_的数据)
 * @param message_type 信息类型
 * @return uint16_t 信息数
 */
ptr->message_num(MessageType_e message_type)

/**
 * @brief 获取示例工作状态(成员变量working_statue_的数据)
 * @return WorkingStatus_e 工作状态
 */
ptr->working_statue()

/**
 * @brief 写入信息
 * @param message_type 信息类型
 * @param data 存储数据指针
 * @param len 数据长度(单位字节)
 * @return WorkingStatus_e 写入状态
 */
ptr->Write(MessageType_e message_type, uint8_t *data, uint16_t len)
    
/**
 * @brief 读信息
 * @param message_type 信息类型
 * @param data 接收信息数组指针
 * @param start_index 从第几条信息开始读(默认第一条信息的索引是0)
 * @param message_num 读几条信息
 * @return WorkingStatus_e 读取状态
 *
 * @attention 不会检查data大小, 警惕data数组越界
 */
ptr->Read(MessageType_e message_type, void *data, uint16_t start_index, uint16_t message_num)
//ptr->Read(message_type, data, 0, ptr->message_num(message_type)) 可以获取指定区域全部信息

/**
 * @brief 重新配置flash, 此操作会清空log
 * @param config 重设的配置
 * @return WorkingStatus_e 重设情况
 */
ptr->ResetConfig(Log_n::Base_Config_t config)
    
/**
 * @brief 清除所有log, 不会清除配置
 * @return WorkingStatus_e 清除状态
 */
ptr->ClearAll()
```



## 3. 其他功能

```c++
/**
 * @brief 获取实际配置区域首地址结构体(只读)
 * @return ZoneAddr_t& 私有成员变量zone_start_addr_
 */
ptr->zone_start_addr();

/**
 * @brief 获取区域当前写到的首地址结构体(只读)
 * @return ZoneAddr_t& 私有成员变量zone_start_addr_
 */
ptr->now_addr();

// 重载了ZoneAddr_t的 "-" "++" 运算符
// 特别的，允许你通过以下方式获取已使用空间的结构体
Log_n::LocalFlash_c::ZoneAddr_t used_space = ptr->now_addr() - ptr->zone_start_addr();
used_space = ptr->now_addr() - ptr->zone_start_addr();
(ptr->now_addr() - ptr->zone_start_addr()).成员;

// 特别的，允许你通过以下方式获取空闲空间的结构体
Log_n::LocalFlash_c::ZoneAddr_t free_space = (++ptr->zone_start_addr()) - ptr->now_addr();
free_space = (++ptr->zone_start_addr()) - ptr->now_addr();
((++ptr->zone_start_addr()) - ptr->now_addr()).成员;

// 特别的，允许你通过以下方式获取配置区域分配的实际空间的结构体
Log_n::LocalFlash_c::ZoneAddr_t zone_space = (++ptr->zone_start_addr()) - ptr->zone_start_addr();
zone_space = (++ptr->zone_start_addr()) - ptr->zone_start_addr();
((++ptr->zone_start_addr()) - ptr->zone_start_addr()).成员;
```



## 4. 注意事项

H7目前必须在32位对齐地址写入并且每32位只能写一次，所以有很多填充的0xFF垃圾数据在Flash里

读取时，已知可能出现以下问题：

1. 当你写入的数据以0xFF结尾时--末尾的0xFF数据在读取时会被忽视
2. 当你读取信息时--每次读取会在你传入的指针末尾填充小于32个0xFF(具体填充数目取决于读取的最后一个信息的32位字节偏移量)，可能导致数组越界
